# UI/UX — wspólny system paneli, kalendarz i hero

Zakres: przegląd źródeł aplikacji i wspólnych komponentów. To nie jest certyfikat
WCAG ani deklaracja, że każdą stronę sprawdzono wizualnie na produkcji. Nowe
scenariusze przeglądarkowe wymagają wyniku CI dokładnego SHA przed publikacją.

## Mapa systemu i kierunek

| Obszar admina / klienta | Wspólny standard / decyzja |
|---|---|
| Dziś / start klienta | Jedna hierarchia: następny krok, termin, historia. Nie kopiujemy klientowi operacyjnych zadań admina. |
| Kalendarz / wolne terminy | Jeden CalendarMonthGrid; różne uprawnienia i treść, identyczny układ i nawigacja. |
| Klienci i projekty / moje projekty i wizyty | Ten sam rytm kart, statusów, pól i fokusów; zarządzanie finansami pozostaje admin-only. |
| Wiadomości / czat | Zachować wspólne komponowanie wiadomości i prywatne media; nie wprowadzać drugiego pollera dla kosmetycznych zmian. |
| Dokumenty / zgody | Wspólne modale i kontrolki; wersjonowanie i potwierdzenia nie mogą zostać ukryte przez kompaktowość. |
| Statystyki, magazyn, lista rezerwowa / profil i powiadomienia | Te same tokeny i stany kontrolek; funkcje pozostają właściwe dla roli. |
| CMS, portfolio, media, ustawienia / publiczna strona | Panel korzysta ze wspólnego UI, ale wygląd opublikowanego projektu jest wyborem autora. |

## Zdiagnozowane różnice i zmiany

1. Pola miały animacje/fokus i cyfry tabelaryczne tylko w adminie. Selektory
   obejmują teraz oba workspace, bez ingerencji w treść publicznych stron.
2. Tytuły paneli miały ciężki krój display. Wspólny studio-page-title używa
   spokojniejszego kroju tekstowego, 26 px, semibold. Tytuły tworzonych stron
   pozostają niezależne.
3. Kalendarz wymuszał 600–680 px i zamieniał pionowe kółko myszy na poziomy
   scroll. Usunięto oba zachowania. Siedem kolumn mieści się w szerokości panelu.
4. Pełne czerwone/zielone paski i 8 px tekst zastąpiono subtelnym tłem,
   bocznym akcentem i 10–11 px opisem. Tekstowe ZAJĘTY/NIEDOSTĘPNY nadal
   rozróżniają status, więc kolor nie jest jedynym nośnikiem informacji.
5. Dzień bieżący ma znacznik oraz aria-current; wybór klienta ma aria-pressed.
   Strzałki przemieszczają fokus o dzień/tydzień, Home/End w obrębie tygodnia.
   Zmiana miesiąca jest ogłaszana; „Dziś” wraca do bieżącego miesiąca.
6. Krótkie pojawienie workspace (220 ms, bez transformacji przodka modali) i przejścia kontrolek
   (140 ms) nie uruchamiają pollingu, zegarów ani nowych bibliotek. Istniejące
   prefers-reduced-motion wyłącza ruch. Nie animujemy wysokości formularzy.
7. Builder domyślnie ma 288 px zamiast 304 px; zapisane preferencje zachowane.
   Kafelki 56 zamiast 64 px, ale podpis 10 zamiast 9 px. Kompaktowość nie
   oznacza pomniejszania tekstu bez granic; coarse pointer nadal ma 44 px.
8. Mobilna regresja wykryła automatycznie otwarty Nawigator zasłaniający
   bibliotekę widgetów. Startuje teraz zamknięty; otwierasz go świadomie
   przyciskiem na pasku. Nie rozwiązano tego wymuszonym kliknięciem przez overlay.
9. Wspólny AppModal: Shift+Tab z początkowego fokusu nie wychodzi już za dialog,
   ukryte kontrolki są pomijane. Zagnieżdżone dialogi mają licznik blokady scrolla
   zamiast wzajemnie odblokowywać stronę. Krótkie pojawienie bez transformacji;
   mobile bez zaokrągleń pełnoekranowej karty. Dotyczy obu paneli.

## Hero · swobodny

Nowy element biblioteki wstawia zwykłe drzewo:

SEKCJA → 2 KOLUMNY → tekst, H1, opis, SEKCJA WEWNĘTRZNA → CTA oraz obraz.

Nie używa portretu właściciela ani stockowego tła. Każdy widget można usunąć,
przenieść lub edytować; można zmienić kolumny i tło, wysokość, odstępy oraz
niezależną typografię desktop/tablet/mobile. Korzysta z istniejącego zapisu,
nawigatora, klonowania i renderera — bez migracji treści zapisanych stron.
Stary szablon Hero pozostaje dostępny dla istniejących projektów.

## Walidacja i granice

- Lokalnie: typecheck, lint zmian, testy struktury hero i operacji drzewa.
- E2E: oba panele desktop/mobile, fokus strzałkami, brak poziomego overflow
  kalendarza, reduced-motion, wstawienie hero i jego publiczna publikacja.
- Same testy automatyczne nie zastępują NVDA, oceny kontrastu nad własnym
  zdjęciem ani ręcznego przeglądu każdego stanu modali i długich formularzy.
- Na wąskim ekranie opisy wydarzeń są skrócone; pełna nazwa dnia/status jest
  w aria-label klienta, szczegóły po wyborze dnia. Dane klienta nigdy nie są
  kopiowane do publicznego kalendarza.
- Wdrożenie nadal zależy od pełnego DR i zamknięcia A10/A14 audytu. Zmiany
  prezentacji nie są powodem do ominięcia bezpieczeństwa lub backup gate.

Rollback: odwrócenie commitu UI. Hero zapisany jako standardowe columns jest
czytelny również przez poprzednią wersję renderera; brak restore bazy.
